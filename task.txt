Техническое задание — аналог Google Docs (Full-Stack)
Задача
Реализовать веб-редактор документов, похожий по духу на Google Docs, с упором на real-
+me совместное редактирование, офлайн-режим и собственный, неповторяющийся
дизайн.
Обязательный минимум (MVP)
1. Текстовый редактор с базовым форматированием: жирный, курсив, заголовки, списки.
2. Real-+me совместное редактирование — два (или больше) пользователя в разных
вкладках/браузерах видят изменения друг друга практически мгновенно, без
перезагрузки страницы.
 - Использовать готовую CRDT/OT-библиотеку (Yjs, Automerge, ShareDB и т.п.) — это
ожидаемо и правильно, писать OT-алгоритм с нуля не нужно и не является плюсом.
3. Офлайн-режим: пользователь может редактировать документ без интернета,
изменения сохраняются локально и корректно синхронизируются (сливаются) при
восстановлении соединения — без потери данных и без "перезаписи" чужих правок.
4. Список докторов / курсоры участников: видно, кто сейчас в документе (имя/цвет), в
идеале — курсор/выделение других пользователей в реальном времени.
5. Сохранение документов (любая БД, в т.ч. локальная/встраиваемая).
Дизайн и UI/UX
- Дизайн должен быть авторским, не копией Google Docs и не дефолтной темой UIфреймворка "как есть".
- Единая система: согласованная палитра цветов, единый набор иконок
(стиль/толщина/размер), выверенные отступы и размеры шрифтов — оценивается
именно системность, а не количество "фич" интерфейса.
- Адаптивность приветствуется, но не обязательна.
Что сдать
- Ссылка на репозиторий + README (запуск, архитектура, почему выбраны эти
инструменты для sync/offline).
- Короткое видео (3–5 мин): 2 пользователя редактируют документ одновременно +
демонстрация офлайн-сценария (отключили сеть → правили → включили → корректно
слилось).
Критерии оценки
- Real-+me синхронизация — работает ли стабильно, нет ли потери/дублирования правок.
- Офлайн-сценарий и merge — самая частая часть, которую делают "для галочки"; здесь
будет отдельное пристальное внимание.
- Архитектура и код — структура, разумность решений, обработка ошибок.
- UI/UX и дизайн — оригинальность, системность цветов/иконок/размеров, удобство
использования.
- Коммуникация — README и видео.
